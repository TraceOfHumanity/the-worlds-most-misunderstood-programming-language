## 1. Історичний контекст

Гвідо ван Россум розпочав роботу над мовою наприкінці 1980-х років у нідерландському Центрі математики та інформатики (CWI) як наступницею мови ABC. Перший публічний випуск відбувся 1991 року. Назву мова отримала не від змії, а від комедійного шоу «Літаючий цирк Монті Пайтона».

Ключові віхи: **Python 2.0** (2000) — збирач циклічних посилань, списові включення; **Python 3.0** (2008) — свідоме порушення зворотної сумісності заради виправлення структурних недоліків (зокрема, стандартна обробка Unicode). Перехід між версіями тривав понад десятиліття, а підтримку Python 2 припинено 1 січня 2020 року. 2018 року ван Россум відмовився від ролі «доброзичливого диктатора на все життя» (BDFL), і мовою відтоді керує виборна рада.

## 2. Принципи дизайну

Філософію мови виражено в тексті **PEP 20** («Дзен Python»), що викликається командою `import this`. Основні положення:

1. **Читабельність має значення.** Синтаксис навмисно мінімальний, а блоки виділяються відступами, а не дужками.
2. **Явне краще за неявне.**
3. **Просте краще за складне.**
4. **Має бути один — і бажано лише один — очевидний спосіб зробити щось.**
5. **«Батарейки в комплекті» (batteries included).** Велика стандартна бібліотека покриває більшість типових завдань.

Стиль коду визначає **PEP 8**, а еволюція мови відбувається через процес **PEP** (Python Enhancement Proposals).

## 3. Модель виконання

Вихідний код компілюється в **байт-код**, який виконує віртуальна машина. Найпоширеніша реалізація — **CPython**, написана мовою [[c]]. Особливість CPython — **глобальне блокування інтерпретатора (GIL)**: в один момент часу байт-код виконує лише один потік, що обмежує паралелізм для обчислювально важких завдань у багатопотокових програмах. Для паралельних обчислень застосовують багатопроцесність або розширення на C/C++. Експериментальний режим без GIL з'явився у версії 3.13.

## 4. Система типів

Python має **динамічну** типізацію: тип належить значенню, а не змінній. Водночас типізація **сильна**: неявних перетворень між несумісними типами немає.

```python
x = 5
x = "текст"          # змінна лише посилається на інше значення
# 5 + "1"            # TypeError — сильна типізація: неявного перетворення немає


def greet(name: str) -> str:   # анотації типів необов'язкові й самі по собі не перевіряються
    return f"Привіт, {name}"


print(greet("світе"))                     # Привіт, світе
print([n * n for n in range(5)])          # [0, 1, 4, 9, 16]
```

Анотації типів (PEP 484) не впливають на виконання; їх перевіряють зовнішні засоби (mypy, pyright). Усе в мові є об'єктом, зокрема цілі числа, функції й класи.

## 5. Керування пам'яттю

Основний механізм — **підрахунок посилань**: об'єкт знищується, щойно кількість посилань на нього стає нульовою. Для циклічних посилань додатково працює збирач сміття. Програміст не керує пам'яттю вручну, але має враховувати життя посилань (наприклад, у кешах і глобальних структурах).

## 6. Екосистема та сфери застосування

- **Наука про дані та машинне навчання:** NumPy, pandas, scikit-learn, PyTorch, TensorFlow.
- **Автоматизація та скриптинг:** адміністрування, обробка файлів.
- **Веб-розробка:** Django, Flask, FastAPI.
- **Наука й освіта:** Jupyter, широке використання в дослідженнях та викладанні.

Швидкодія обчислень у наукових бібліотеках забезпечується тим, що критичні ділянки реалізовано на C/C++/Fortran, а Python слугує «клейовою» мовою над ними.

## 7. Сильні сторони та обмеження

| Сильні сторони | Обмеження |
|---|---|
| Висока читабельність, низький поріг входу | Нижча швидкодія порівняно з компільованими мовами |
| Величезна екосистема бібліотек | GIL обмежує багатопотоковий паралелізм |
| Універсальність (від скриптів до ШІ) | Динамічна типізація: помилки проявляються під час виконання |
| Інтерактивність (REPL, Jupyter) | Розгортання та керування залежностями |

## 8. Поширені хибні уявлення

1. «Python — інтерпретована мова, компіляції немає». Насправді компіляція в байт-код відбувається, лише результат прихований.
2. «Динамічна типізація означає слабку». Python — динамічна й водночас сильна.
3. «Python занадто повільний для серйозної роботи». Для обчислень у науковій екосистемі це здебільшого невірно, бо важкі ділянки виконуються скомпільованими бібліотеками.
4. «Відступи — це косметика». Вони є частиною синтаксису.
